PROYECTO: Comuniapp (Gestión Social Offline-First)

FECHA DE EVALUACIÓN: 22 de Julio de 2026

--------------------------------------------------------------------------------
1. RESUMEN EJECUTIVO
--------------------------------------------------------------------------------
Comuniapp procesa información altamente sensible referente a la gestión comunitaria,
censos poblacionales, solicitudes de ayudas sociales, reportes de infraestructura
y datos personales de habitantes. Debido a la arquitectura "Offline-First", existe
una dualidad de almacenamiento entre el dispositivo móvil (Hive) y la nube (MongoDB).

La evaluación del código fuente reveló vulnerabilidades críticas relativas a:
1. Autenticación débil mediante encabezados manipulables (`x-user-role`, `x-username`).
2. Almacenamiento local en texto plano en la base de datos Hive.
3. Ausencia de middleware de autorización y hardening HTTP en el servidor backend.
4. Falta de limitación de tasa (Rate Limiting) y control de acceso a archivos estáticos.

--------------------------------------------------------------------------------
2. DIAGNÓSTICO DE HALLAZGOS Y VULNERABILIDADES DETECTADAS
--------------------------------------------------------------------------------

[HALLAZGO #1] Autenticación insegura por encabezados personalizados
- Ubicación: lib/core/services/mongodb_service.dart
- Descripción: El interceptor de Dio inyecta el rol y nombre de usuario leyendo
  directamente el estado local (`user.role`, `user.username`) en los encabezados HTTP.
- Riesgo: Altísimo. Cualquier atacante o usuario malintencionado con un proxy HTTP
  (Burp Suite / OWASP ZAP) puede alterar la petición para enviar 'x-user-role: admin'
  y suplantar privilegios en el backend.

[HALLAZGO #2] Almacenamiento local en texto plano sin cifrado
- Ubicación: lib/core/services/hive_config.dart
- Descripción: Las cajas de Hive (`habitants`, `censos`, `user_session`, etc.)
  se abren sin utilizar una clave de cifrado criptográfica.
- Riesgo: Alto. Si el dispositivo móvil se pierde, es robado o cuenta con acceso de
  superusuario (root/jailbreak), un tercero puede extraer y leer todas las bases de
  datos SQLite/Hive de la aplicación.

[HALLAZGO #3] Backend expuesto y falta de Bastionado (Hardening)
- Ubicación: backend/src/index.js
- Descripción: El servidor Express usa CORS abierto a cualquier origen (`cors()`),
  carece de cabeceras de seguridad HTTP (`helmet`), no tiene Rate Limiting activo, y
  los archivos estáticos `/uploads` se sirven de forma pública sin control de sesión.
- Riesgo: Alto. Expone el servidor a ataques de fuerza bruta, XSS, Clickjacking, y
  denegación de servicio (DoS).

[HALLAZGO #4] Falta de firmado y validación criptográfica de tokens (JWT)
- Ubicación: backend/src/routes/ y backend/src/controllers/
- Descripción: No se valida de forma centralizada si las solicitudes provienen de
  una sesión autenticada ni se verifica la expiración de la sesión mediante JWT.

--------------------------------------------------------------------------------
3. PROTOCOLOS DE CIBERSEGURIDAD A IMPLEMENTAR
--------------------------------------------------------------------------------

PROTOCOLO 1: Autenticación Basada en Tokens JWT (JSON Web Tokens)
  - Firma obligatoria HMAC-SHA256 o RSA para autenticación y autorización.
  - Expiración de Access Tokens a corto plazo (15 a 30 min) y uso de Refresh Tokens.

PROTOCOLO 2: Cifrado en Reposo de Datos Sensibles (Data at Rest Encryption)
  - Implementación de clave de cifrado de 256 bits (`HiveAesCipher`) generada por Hive.
  - Almacenamiento seguro de la clave en Android Keystore / iOS Keychain mediante
    `flutter_secure_storage`.

PROTOCOLO 3: Protección de Datos en Tránsito y TLS Pinning (Data in Transit)
  - Restricción estricta de tráfico a HTTPS/TLS 1.3.
  - Implementación opcional de SSL Certificate Pinning en Dio para la URL del backend
    (Render.com).

PROTOCOLO 4: Bastionado (Hardening) del API Backend
  - Cabeceras de seguridad mediante `helmet`.
  - Limitación de tasa de solicitudes (`express-rate-limit`) para prevenir fuerzabuta.
  - Sanitización de entradas contra inyecciones NoSQL (`express-mongo-sanitize`).
  - Restricción de dominios cruzados en CORS.

PROTOCOLO 5: Almacenamiento Seguro de Credenciales (Password Hashing)
  - Hashing obligatorio de contraseñas con `bcrypt` (factor de costo >= 12).

PROTOCOLO 6: Gestión de Entorno, Logs Sanitizados y Ofuscación de Código
  - Eliminación de logs en producción que expongan datos personales o tokens.
  - Uso de variables de entorno protegidas (`.env`).
  - Habilitación de ProGuard / R8 para ofuscar el binario compilado de la aplicación.

CORRECCIÓN A: Implementar Middleware JWT y Bastionado en Backend (Node.js/Express)
--------------------------------------------------------------------------------
Archivo objetivo: backend/src/middleware/auth.middleware.js (NUEVO)

```javascript
const jwt = require('jsonwebtoken');

const verifyToken = (req, res, next) => {
    const authHeader = req.headers['authorization'];
    const token = authHeader && authHeader.split(' ')[1]; // Format: "Bearer <TOKEN>"

    if (!token) {
        return res.status(401).json({ success: false, message: 'Acceso denegado. Token no proporcionado.' });
    }

    try {
        const verified = jwt.verify(token, process.env.JWT_SECRET);
        req.user = verified; // { id, username, role, iat, exp }
        next();
    } catch (error) {
        return res.status(403).json({ success: false, message: 'Token inválido o expirado.' });
    }
};

const authorizeRoles = (...allowedRoles) => {
    return (req, res, next) => {
        if (!req.user || !allowedRoles.includes(req.user.role)) {
            return res.status(403).json({ success: false, message: 'No tiene permisos para realizar esta acción.' });
        }
        next();
    };
};

module.exports = { verifyToken, authorizeRoles };
```

CORRECCIÓN B: Hardening del servidor Express (Seguridad HTTP)
--------------------------------------------------------------------------------
Archivo objetivo: backend/src/index.js

```javascript
const express = require('express');
const cors = require('cors');
const helmet = require('helmet');
const rateLimit = require('express-rate-limit');
const mongoSanitize = require('express-mongo-sanitize');
const dotenv = require('dotenv');
const connectDB = require('./config/db');

dotenv.config();
connectDB();

const app = express();

// 1. Cabeceras HTTP de Seguridad
app.use(helmet());

// 2. Control de CORS restringido
const allowedOrigins = process.env.ALLOWED_ORIGINS 
    ? process.env.ALLOWED_ORIGINS.split(',') 
    : ['http://localhost:3000'];

app.use(cors({
    origin: (origin, callback) => {
        if (!origin || allowedOrigins.includes(origin)) {
            callback(null, true);
        } else {
            callback(new Error('Bloqueado por política de CORS'));
        }
    },
    credentials: true
}));

// 3. Limitación de peticiones (Prevenir Fuerza Bruta y DoS)
const limiter = rateLimit({
    windowMs: 15 * 60 * 1000, // 15 minutos
    max: 100, // Límite de 100 peticiones por IP
    message: { success: false, message: 'Demasiadas solicitudes. Intente más tarde.' }
});
app.use('/v1/', limiter);

// 4. Parseo de body y Sanitización NoSQL
app.use(express.json({ limit: '5mb' }));
app.use(mongoSanitize());

// 5. Rutas con Middleware de Auth
const { verifyToken } = require('./middleware/auth.middleware');

app.use('/v1/habitants', verifyToken, require('./routes/habitants.route'));
app.use('/v1/reports', verifyToken, require('./routes/reports.route'));
app.use('/v1/censos', verifyToken, require('./routes/censos.route'));
app.use('/v1/censo_records', verifyToken, require('./routes/censo_records.route'));
app.use('/v1/ayudas', verifyToken, require('./routes/ayudas.route'));
app.use('/v1/eventos', verifyToken, require('./routes/eventos.route'));
app.use('/v1/stats', verifyToken, require('./routes/stats.route'));
app.use('/v1/auditoria', verifyToken, require('./routes/auditoria.route'));
app.use('/v1/users', require('./routes/users.route')); // Rutas públicas de Login/Auth

const PORT = process.env.PORT || 3000;
app.listen(PORT, '0.0.0.0', () => {
    console.log(`Servidor seguro corriendo en puerto ${PORT}`);
});
```

CORRECCIÓN C: Actualizar Interceptor de Dio para Tokens JWT (Flutter)
--------------------------------------------------------------------------------
Archivo objetivo: lib/core/services/mongodb_service.dart

```dart
// En lugar de enviar x-user-role y x-username en texto plano:
_dio.interceptors.add(InterceptorsWrapper(
  onRequest: async (options, handler) async {
    try {
      // Obtener el JWT token guardado de forma segura
      final token = await SecureStorageService.getAuthToken();
      if (token != null && token.isNotEmpty) {
        options.headers['Authorization'] = 'Bearer $token';
      }
    } catch (e) {
      debugPrint('Error inyectando Token JWT: $e');
    }
    handler.next(options);
  },
  onError: (DioException e, handler) {
    if (e.response?.statusCode == 401) {
      // Manejar token expirado -> Redirigir a Login
    }
    handler.next(e);
  }
));
```

CORRECCIÓN D: Cifrado de Base de Datos Local Hive (Flutter)
--------------------------------------------------------------------------------
Archivo objetivo: lib/core/services/hive_config.dart

```dart
import 'dart:convert';
import 'package:flutter_secure_storage/flutter_secure_storage.dart';
import 'package:hive_flutter/hive_flutter.dart';

class HiveConfig {
  static const _secureStorage = FlutterSecureStorage();

  static Future<List<int>> _getOrCreateEncryptionKey() async {
    const keyName = 'hive_master_encryption_key';
    final existingKey = await _secureStorage.read(key: keyName);
    
    if (existingKey != null) {
      return base64Url.decode(existingKey);
    } else {
      final newKey = Hive.generateSecureKey();
      await _secureStorage.write(
        key: keyName, 
        value: base64UrlEncode(newKey)
      );
      return newKey;
    }
  }

  static Future<void> init() async {
    await Hive.initFlutter();
    
    // Registrar adaptadores...
    
    // Obtenemos clave cifrada única desde el Keystore/Keychain
    final encryptionCipher = HiveAesCipher(await _getOrCreateEncryptionKey());

    // Abrir cajas con cifrado AES-256
    await Hive.openBox(habitantsBox, encryptionCipher: encryptionCipher);
    await Hive.openBox(reportsBox, encryptionCipher: encryptionCipher);
    await Hive.openBox(userBox, encryptionCipher: encryptionCipher);
    await Hive.openBox(censosBox, encryptionCipher: encryptionCipher);
    await Hive.openBox(censoRecordsBox, encryptionCipher: encryptionCipher);
  }
}
```
